# بات پیام ناشناس بله (Bale)

یک بات پیام‌رسانِ ناشناس برای پیام‌رسان بله، همراه با:
- انتخاب اختیاری نام مستعار توسط کاربر
- ارسال/دریافت پیام از داخل خودِ چت بات
- یک **مینی‌اپ** که شماره‌ی کاربر رو می‌گیره، پروفایلش (نام مستعار) رو نشون می‌ده
  و امکان چت ناشناس رو از همون‌جا فراهم می‌کنه
- ورود ادمین با یک لینک/توکن مخصوص (`/start <ADMIN_TOKEN>`) که پس از آن،
  همون مینی‌اپ به‌جای نمای «چت کاربر»، **پنل ادمین** رو نشون می‌ده
  (لیست گفتگوها + امکان پاسخ ناشناس)

## ساختار پروژه

```
anon_bale_bot/
├── app.py              # اپ فلَسک: وبهوک بات + API مینی‌اپ
├── bale_api.py          # لایه‌ی ارتباط با Bot API بله
├── database.py           # sqlite (کاربران / پیام‌ها / نگاشت پاسخ‌ها)
├── miniapp_auth.py        # اعتبارسنجی initData ارسالی از مینی‌اپ
├── config.py               # خواندن تنظیمات از .env
├── templates/miniapp.html
├── static/style.css
├── static/app.js
├── requirements.txt
└── .env.example
```

## مراحل راه‌اندازی

### ۱. ساخت بات و گرفتن توکن
در بله به `@botfather` پیام بده، یک بات جدید بساز و توکن رو بگیر.
از همون‌جا (طبق مستندات مینی‌اپ‌های بله) دکمه‌ی منوی بات و/یا آدرس مینی‌اپ رو هم می‌تونی تنظیم کنی.

### ۲. آماده‌سازی محیط
```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# .env رو با ویرایشگر باز کن و مقادیر واقعی رو بذار:
#   BOT_TOKEN, BASE_URL, WEBHOOK_SECRET_PATH, ADMIN_START_TOKEN
```

`BASE_URL` باید آدرس **HTTPS عمومی** سروری باشه که این پروژه روش دیپلوی می‌شه
(بله هم برای webhook و هم برای مینی‌اپ، HTTPS معتبر می‌خواد).

### ۳. اجرا (پروداکشن)
```bash
gunicorn -w 2 -b 0.0.0.0:5000 app:app
```
و پشت یک reverse proxy (nginx/caddy) با گواهی SSL معتبر قرارش بده.

برای تست اولیه‌ی محلی هم می‌تونی مستقیم اجرا کنی:
```bash
python app.py
```

### ۴. ثبت وبهوک
بعد از بالا اومدن سرور، یک‌بار این آدرس رو در مرورگر باز کن:
```
https://your-domain.example.com/setup-webhook
```
این کار `setWebhook` رو با آدرس `BASE_URL/webhook/WEBHOOK_SECRET_PATH` صدا می‌زنه.
بعد از تست، بهتره این مسیر (`/setup-webhook` در `app.py`) رو حذف یا محدود کنی.

### ۵. استفاده
- **کاربر عادی:** با زدن `/start` وارد بات می‌شه، می‌تونه نام مستعار بذاره یا رد کنه،
  و پیام بده. همچنین دکمه‌ی «باز کردن مینی‌اپ» رو داره.
- **ادمین:** باید با لینک ویژه وارد بشه:
  ```
  https://ble.ir/YOUR_BOT_USERNAME?start=ADMIN_START_TOKEN
  ```
  (مقدار `ADMIN_START_TOKEN` همون چیزیه که در `.env` گذاشتی.)
  با این کار، چت‌آی‌دیِ اون کاربر به عنوان ادمین ثبت می‌شه، ازش شماره تلفن
  گرفته می‌شه، و وقتی مینی‌اپ رو باز کنه، به‌جای نمای چت، **پنل ادمین**
  (لیست کاربران/پیام‌ها + پاسخ‌گویی) رو می‌بینه.
- ادمین می‌تونه هم از داخل خودِ چت بات (با ریپلای‌کردن روی پیام فوروارد شده)
  و هم از داخل مینی‌اپ، پاسخ ناشناس بده.

## عضویت اجباری در کانال‌ها

قبل از پردازش **هر پیام** (چه از کاربر عادی، چه از ادمین — چه در خودِ چت
بات، چه از داخل مینی‌اپ)، عضویت کاربر در کانال‌های زیر بررسی می‌شه:

- `@sharif_for_iran`
- `@rahbar_ir`

این لیست در `config.REQUIRED_CHANNELS` قابل ویرایش/افزودن/حذفه.

⚠️ **نکته‌ی فنی مهم:** برای اینکه بات بتونه با متد `getChatMember` عضویت
یک کاربر در یک کانال رو چک کنه، معمولاً باید **خودِ بات به عنوان ادمین
(یا حداقل عضو) اون کانال** اضافه شده باشه؛ وگرنه فراخوانی با خطا مواجه
می‌شه. کد فعلی طوری نوشته شده که در صورت خطا در گرفتن وضعیت عضویت،
به‌صورت محافظه‌کارانه فرض می‌کنه کاربر عضو نیست (یعنی جلوی استفاده از
بات رو می‌گیره) — پس حتماً قبل از فعال کردن نهایی، بات رو به هر دو
کانال (به‌عنوان ادمین) اضافه کن و تست بگیر که `getChatMember` جواب درست
می‌ده.

اگه کاربر عضو نباشه، پیامی با دو دکمه‌ی «عضویت در کانال» + دکمه‌ی
«✅ عضو شدم، بررسی کن» (که دوباره چک می‌کنه) براش ارسال می‌شه؛ در مینی‌اپ
هم همین بررسی روی مسیر `/api/send` انجام می‌شه و در صورت عدم عضویت،
لینک کانال‌ها به کاربر نشون داده می‌شه.

## دریافت شماره تلفن در مینی‌اپ

طبق آخرین درخواست، **شماره تلفن در مینی‌اپ فقط از کسی گرفته می‌شه که از
طریق لینک/توکن ادمین (`/start ADMIN_START_TOKEN`) وارد شده** (یعنی
`is_admin=1`). برای کاربران عادی، مینی‌اپ اصلاً درخواست شماره نمی‌ده و
مستقیم وارد نمای چت می‌شه؛ سمت بک‌اند هم مسیر `/api/phone` رو برای
کاربر غیرادمین با خطای ۴۰۳ رد می‌کنه، تا حتی با دستکاری فرانت‌اند هم
شماره‌ی کاربر عادی ذخیره نشه.

## نکات مهم / محدودیت‌های شناخته‌شده

1. **API مینی‌اپ بله (`window.Bale.WebApp`)** دقیقاً از الگوی WebApp تلگرام
   پیروی می‌کنه (اسکریپت `https://tapi.bale.ai/miniapp.js`، همون مفهوم
   `initData`، `ready()`، `expand()` و غیره) — طبق مستندات رسمی
   `docs.bale.ai/miniapp`. اما **نام دقیق متد گرفتن شماره تلفن** (که در
   کد از `requestContact` و به‌عنوان جایگزین از `requestPhoneNumber`
   استفاده شده) رو حتماً قبل از انتشار نهایی، با آخرین نسخه‌ی همون صفحه‌ی
   مستندات مطابقت بده — چون من نتونستم مستقیماً به اون صفحه دسترسی
   خودکار داشته باشم (robots آن سایت اجازه fetch خودکار نمی‌ده) و این
   بخش رو بر اساس شباهت مستندشده‌ی این پلتفرم با تلگرام نوشتم.
2. اگه متد خودکار جواب نداد، به‌عنوان راه جایگزینِ ۱۰۰٪ مطمئن، یک دکمه‌ی
   «اشتراک مخاطب» هم داخل خودِ چت بات (روش استاندارد Bot API، دقیقاً مثل
   تلگرام) پیاده‌سازی شده که همیشه کار می‌کنه.
3. اعتبارسنجی `initData` (امضای HMAC-SHA256 با کلید مشتق‌شده از توکن بات)
   هم بر همون الگوی استاندارد WebApp نوشته شده؛ اگه در عمل با خطای ۴۰۱
   مواجه شدی، بخش `miniapp_auth.py` رو با فرمت واقعیِ initData ای که
   بله می‌فرسته (با `console.log(WebApp.initData)` داخل مینی‌اپ) مطابقت بده.
4. دیتابیس فعلی sqlite ساده‌ست؛ برای ترافیک بالا بهتره به Postgres/MySQL
   مهاجرت کنی.
5. برای تست بدون اپ واقعی بله، `DEV_MODE=1` رو در `.env` بذار — در این
   حالت مینی‌اپ یک `chat_id` دستی از خودت می‌پرسه (فقط برای توسعه، در
   پروداکشن حتماً خاموشش کن).

## جریان دیتا (خلاصه)
```
کاربر عادی --/start--> بات --> (اختیاری) نام مستعار --> پیام متنی
    پیام --> ذخیره در دیتابیس --> فوروارد به همه‌ی ادمین‌ها
ادمین --ریپلای روی پیام فوروارد شده یا از داخل مینی‌اپ--> پاسخ ناشناس به همون کاربر

ادمین جدید --/start ADMIN_START_TOKEN--> علامت‌گذاری is_admin=1 --> درخواست شماره
مینی‌اپ (چه کاربر چه ادمین) --initData--> /api/auth --> اگه is_admin بود
    پنل ادمین (لیست گفتگوها) وگرنه چت شخصی خودش رو می‌بینه
```
