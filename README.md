# بات پیام ناشناس بله (Bale)

یک بات پیام‌رسانِ ناشناس برای پیام‌رسان بله، همراه با:

- هر کاربر یک `uuid` یکتا داره؛ اگه نام مستعار نذاره، به‌صورت
  «ناشناس `<uuid>`» نمایش داده می‌شه.
- انتخاب اختیاری نام مستعار توسط کاربر (با `/nickname` قابل تغییره).
- عضویت اجباری در چند کانال مشخص، قبل از پردازش **هر پیام** (چه از
  کاربر عادی، چه از ادمین).
- یک **پنل ادمین** به‌صورت مینی‌اپ (فقط برای ادمین قابل دسترسیه؛
  کاربر عادی اصلاً نمی‌تونه واردش بشه) با امکانات:
  - دیدن لیست گفتگوها و پاسخ ناشناس به هرکدوم
  - مسدود کردن / رفع مسدودیت یک کاربر
  - حذف کامل گفتگوی یک کاربر
  - نمایش پیام سیستمی «کاربر نام مستعارش رو تغییر داد» داخل گفتگو
- ورود ادمین با یک لینک/توکن مخصوص (`/start <ADMIN_TOKEN>`).
- دیتابیس PostgreSQL (به‌جای sqlite قبلی) + Docker/Docker Compose.

## ساختار پروژه

```
anon_bale_bot/
├── app.py              # اپ فلَسک: وبهوک بات + API پنل ادمین
├── bale_api.py          # لایه‌ی ارتباط با Bot API بله
├── database.py           # PostgreSQL (psycopg3 + connection pool)
├── miniapp_auth.py        # اعتبارسنجی initData ارسالی از مینی‌اپ
├── config.py               # خواندن تنظیمات از .env
├── templates/miniapp.html   # پنل ادمین (تنها UI مینی‌اپ)
├── static/style.css
├── static/app.js
├── requirements.txt
├── Dockerfile
├── docker-compose.yml
├── .dockerignore
└── .env.example
```

## راه‌اندازی سریع با Docker (پیشنهادی)

### ۱. آماده‌سازی `.env`
```bash
cp .env.example .env
```
مقادیر زیر رو حتماً پر کن:
- `BOT_TOKEN` — از `@botfather`
- `BASE_URL` — آدرس HTTPS عمومی سروری که این پروژه روش دیپلوی می‌شه
- `WEBHOOK_SECRET_PATH` — یک رشته‌ی تصادفی (`python3 -c "import secrets;print(secrets.token_urlsafe(24))"`)
- `ADMIN_START_TOKEN` — یک رشته‌ی تصادفی و محرمانه

(نیازی نیست `DATABASE_URL` رو دستکاری کنی؛ در `docker-compose.yml` به‌طور خودکار به سرویس `db` وصل می‌شه.)

### ۲. بالا آوردن سرویس‌ها
```bash
docker compose up -d --build
```
این کار یک کانتینر PostgreSQL و یک کانتینر اپ (با gunicorn روی پورت ۵۰۰۰) بالا میاره.
جدول‌های دیتابیس به‌صورت خودکار موقع بالا اومدن اپ ساخته می‌شن.

### ۳. ثبت وبهوک
بعد از اینکه سرویس‌ها بالا اومدن و از پشت یک reverse proxy (nginx/caddy) با
SSL معتبر به `BASE_URL` متصل شدن، یک‌بار این آدرس رو باز کن:
```
https://your-domain.example.com/setup-webhook
```
بعد از تست، بهتره این مسیر رو در `app.py` غیرفعال/حذف کنی.

## اجرای بدون Docker (اختیاری)

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # و مقادیر رو پر کن، از جمله DATABASE_URL به یک PostgreSQL محلی
gunicorn -w 2 -b 0.0.0.0:5000 app:app
```
باید از قبل یک دیتابیس PostgreSQL بالا داشته باشی و `DATABASE_URL` رو به‌درستی تنظیم کنی؛ جدول‌ها موقع اجرا خودکار ساخته می‌شن.

## استفاده

- **کاربر عادی:** با زدن `/start` وارد بات می‌شه، می‌تونه نام مستعار
  بذاره یا رد کنه (در این صورت به‌عنوان «ناشناس `<uuid>`» نمایش داده
  می‌شه)، و پیام بده. با `/nickname` هم می‌تونه هر وقت نامش رو عوض کنه —
  این تغییر به‌صورت یک پیام سیستمی داخل گفتگوش برای ادمین ثبت می‌شه.
  کاربر عادی به مینی‌اپ/پنل ادمین دسترسی نداره.
- **ادمین:** باید با لینک ویژه وارد بشه:
  ```
  https://ble.ir/YOUR_BOT_USERNAME?start=ADMIN_START_TOKEN
  ```
  بعدش ازش شماره تلفن گرفته می‌شه (هم از طریق دکمه‌ی داخل چت، هم موقع
  باز کردن پنل ادمین در مینی‌اپ). داخل پنل ادمین می‌تونه:
  - لیست همه‌ی گفتگوها رو ببینه
  - وارد هر گفتگو بشه و پاسخ ناشناس بده
  - کاربر رو مسدود/رفع‌مسدود کنه
  - کل گفتگوی یک کاربر رو حذف کنه
  - همچنین می‌تونه از داخل خودِ چت بات، با ریپلای‌کردن روی پیام
    فوروارد شده، پاسخ بده.

## عضویت اجباری در کانال‌ها

قبل از پردازش **هر پیام** (چه کاربر عادی، چه ادمین — چه در چت بات، چه
از داخل پنل ادمین در مینی‌اپ)، عضویت کاربر در کانال‌های زیر بررسی می‌شه:

- `@sharif_for_iran`
- `@rahbar_ir`

این لیست در `config.REQUIRED_CHANNELS` قابل ویرایش/افزودن/حذفه.

⚠️ **نکته‌ی فنی مهم:** برای اینکه بات بتونه با متد `getChatMember` عضویت
یک کاربر در یک کانال رو چک کنه، باید **خودِ بات به عنوان ادمین (یا
حداقل عضو) اون کانال** اضافه شده باشه؛ وگرنه فراخوانی fail می‌شه و کد
به‌صورت محافظه‌کارانه فرض می‌کنه کاربر عضو نیست (یعنی جلوی استفاده از
بات رو می‌گیره). قبل از فعال‌سازی نهایی، بات رو به هر دو کانال اضافه
کن و تست بگیر.

## نکات مهم / محدودیت‌های شناخته‌شده

1. **API مینی‌اپ بله (`window.Bale.WebApp`)** از الگوی WebApp تلگرام
   پیروی می‌کنه، ولی نام دقیق متد گرفتن شماره تلفن (`requestContact` /
   `requestPhoneNumber`) رو حتماً قبل از انتشار نهایی با آخرین نسخه‌ی
   `docs.bale.ai/miniapp` مطابقت بده. اگه خودکار جواب نداد، راه جایگزینِ
   ۱۰۰٪ مطمئن (دکمه‌ی اشتراک مخاطب داخل خودِ چت بات) همیشه در دسترسه.
2. اعتبارسنجی `initData` (امضای HMAC-SHA256) بر همون الگوی استاندارد
   WebApp نوشته شده؛ در صورت خطای ۴۰۱ مکرر، `miniapp_auth.py` رو با
   فرمت واقعیِ initData ای که بله می‌فرسته مطابقت بده.
3. برای تست بدون اپ واقعی بله، `DEV_MODE=1` رو در `.env` بذار — در این
   حالت پنل ادمین یک `chat_id` دستی از خودت می‌پرسه (فقط برای توسعه، در
   پروداکشن حتماً خاموشش کن).
4. مسیر `/setup-webhook` بعد از اولین استفاده باید غیرفعال یا محدود
   بشه، چون بدون احراز هویته.

## جریان دیتا (خلاصه)
```
کاربر عادی --/start--> بات --> (اختیاری) نام مستعار --> پیام متنی
    پیام --> ذخیره در دیتابیس --> فوروارد به همه‌ی ادمین‌ها
    تغییر نام مستعار --> ثبت به‌صورت پیام سیستمی در همون گفتگو

ادمین --ریپلای روی پیام فوروارد شده یا از داخل پنل--> پاسخ ناشناس به همون کاربر
ادمین --از پنل--> مسدود/رفع‌مسدود کردن کاربر، یا حذف کامل گفتگوش

ادمین جدید --/start ADMIN_START_TOKEN--> علامت‌گذاری is_admin=1 --> درخواست شماره
پنل ادمین (مینی‌اپ) --initData--> /api/auth --> فقط اگه is_admin بود اجازه‌ی ورود می‌ده
```
